# Surffish v0.1.35

Surffish connects managed SSH tunnels with a built-in SSH client, adds a System OpenSSH option, moves connection settings to their own tab and gives the macOS app its own executable identity.

## New

- **Built-in SSH client**: managed SSH tunnels now connect with an in-app SSH client that reads `~/.ssh/config` (IdentityFile, Port, User, Include, simple Match rules), the default keys in `~/.ssh`, `known_hosts` and ssh-agent, and explains failed authentication. Non-default ports work without the system `ssh` binary. (527bffc, 3b6f613, bf218fe, a1640e4, de1719b)
- **SSH client choice**: Settings → **Connection** → **SSH client** switches between Built-in (default) and System OpenSSH, which runs `/usr/bin/ssh` with the full SSH configuration and agent for ProxyJump, ProxyCommand, Match exec, certificates and security keys. Changing it restarts the tunnel on Save. (#303)
- **Connection settings**: the SOCKS5 proxy, managed SSH tunnel, local-network bypass, kill switch, shared listener activity and network rules moved from General to a new Settings → **Connection** section. Settings search, the command palette (**Settings: Connection**) and `surffish://settings?section=connection` lead there; older links to General → Connection redirect. (#303)

## Fixed

- macOS now treats Surffish as its own app for per-app privacy settings such as Local Network access, instead of sharing the identity every Electron app ships with. (#302)

## CI

- Fixed the settings-search smoke index reader, the knip config and the app-payload test after the formatter switch; added a macOS UUID test build workflow. (#302, #303)

## Packaging

- The main executable gets a Surffish-specific LC_UUID and the app is re-signed ad hoc after packaging. macOS may ask again once for permissions such as Local Network. (#302)
- Apple silicon zip only, unsigned and not notarized. If macOS reports the app as damaged, run `xattr -cr /Applications/Surffish.app` on a copy downloaded from the official release.
