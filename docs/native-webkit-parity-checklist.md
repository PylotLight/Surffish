# Surffish Native WebKit parity checklist

**Electron reference:** [`origin/main` at `fbabc6aa03ba3b39eee92ed4388c39fa919f3b87`](https://github.com/PylotLight/Surffish/tree/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87), pinned to Electron `46.0.0-alpha.12`. The local `main` branch is stale and is not a comparison source.
**Native working branch:** `poc/native-webkit-app`, including this current code pass. The native implementation is Swift/AppKit/WebKit/Network.framework for macOS 26+ arm64; it is intentionally not an Electron/Chromium port.
**Roadmap:** [`native-webkit-mvp-roadmap.md`](native-webkit-mvp-roadmap.md).

Status labels distinguish code from verified parity. **Implemented in code (source checks pass; macOS build verified; runtime QA pending)** means the current feature code has passed a native build on its cited source commit; interactive behavior remains unverified. **Source-checked (macOS build pending; runtime QA pending)** means deterministic contracts pass but no native build has passed for the relevant source. Prior code commit `7c1ec82` has a successful macOS build, but it predates the downloads follow-up. **Partial** means a useful native foundation exists but important Electron behavior is missing; **Missing** means no equivalent is present; **Native alternative required** means a Chromium feature must not be represented as a direct WebKit port.

## Snapshot

This is a substantial native parity tranche, not full Electron parity. The SwiftUI compact rail/full panel is coordinated with the browser shell and AppKit-hosted WebKit page card. Earlier follow-ups added searchable library panels; pinned/unpinned tab reorder; a separate persistent keep-open pin; and drag-resizable sidebar width. The prior code pass added searchable Settings, editable/reorderable profile-local New Tab shortcuts, clock preferences, history time/site clearing and lazy restore. The latest follow-up moves Settings out of the collapsed rail to match Electron's control placement, adds pinned-bookmark reorder within its pin partition, and adds opt-in History retention. Profile-local per-origin zoom, private-session overrides, per-panel sorting and approximate Find feedback remain in place. Downloads now have a native WebKit-backed foundation and user-facing controls, but are not full Electron parity: WebKit has no pause API, and resume is conditional on supplied resume data plus a live originating WebView. Common navigation failures and terminated WebKit page processes now have a local recovery surface; this error-recovery addition still needs a macOS build and interactive runtime QA. Permissions/certificate UI and broad content tools remain incomplete.

## Product and interface checklist

### Browser shell, frame, sidebar and rail

- **Single sidebar-collapse affordance — Implemented; regression-checked.** The sidebar itself does not render a second collapse button; the toolbar owns the single toggle. `scripts/native-poc-ui-contract.test.cjs` checks this contract.
- **Translucent macOS frame and inset page card — Partial.** The SwiftUI shell coordinates toolbar, sidebar and page-card geometry; AppKit still provides the window, titlebar hit-testing and `NSVisualEffectView` desktop vibrancy, while WebKit owns page rendering. The native effect cannot sample/blur remote web content as Electron's compositor does; this is a native backdrop, not identical compositor behavior.
- **Collapsed rail — Implemented in code (macOS 26 build verified on `7c1ec82`; runtime QA pending).** A 64-point persistent SwiftUI rail has a first-pinned-item cluster, open unpinned-tab marks, New Tab and a distinct keep-open pin action; Settings remains in the expanded panel, matching Electron's control placement. Expanding switches to a full SwiftUI panel; tab and first-pin marks use `matchedGeometryEffect`, and a 180 ms hover-exit grace plus focus/reveal locks coordinate the transition. Sidebar width is user-resizable from 220–440 points and saved; the expanded inner panel tracks the shell's changing width. The page card shifts with the shell width. Electron's measured DOM/FLIP choreography and compositor/backdrop locks are not claimed as equivalent. See the [Electron rail implementation](https://github.com/PylotLight/Surffish/blob/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87/src/renderer/src/views/browser/SidebarRail.tsx) and [browser shell](https://github.com/PylotLight/Surffish/blob/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87/src/renderer/src/views/Browser.tsx).
- **Sidebar panels — Implemented in code (macOS 26 build verified on `7c1ec82`; runtime QA pending).** Tabs, History, Bookmarks and Reading List are searchable by title, URL and host; library panels show counts for visible filtered rows and each retains its own sort choice (Default, Newest, Oldest, Title A–Z, Title Z–A). Tabs can be dragged within their pinned/unpinned partition; pinned tabs/sites appear in the expanded panel and compact cluster; pinned bookmarks can be reordered and persist within their pinned/unpinned partition. Group/Space integration, multi-select, and exact Electron reveal/resize behavior remain open.
- **Toolbar and overflow — Partial.** Native has back, forward, reload/stop, tabs/history/bookmarks, bookmark, address field, progress and Bramble/extension actions. Electron has a broader customizable toolbar/overflow surface; native has no equivalent layout customization.
- **Sidebar collapse/expand animation — Partial.** SwiftUI animates rail/panel changes and shell/page-card width with matched geometry, hover delay and focus/reveal state; the expanded panel is now resizable. Native does not reproduce Electron's full pixel-measured morph, cursor sampling or compositor backdrop coordination; verify interactive timing on macOS.

### Navigation, omnibox and New Tab

- **Back, forward, reload/stop and load progress — Partial, improved in code.** The native toolbar wires to each tab's `WKWebView`; right-clicking Back or Forward opens that tab's WebKit history and selecting an entry navigates to it. Failed provisional/committed loads now show a local recovery panel with a safe error summary, retry, and Back/New Tab actions; WebKit content-process termination has a reload path, and user-cancelled loads do not show an error page. Certificate failures never offer a bypass. Full navigation state, lifecycle recovery and Electron behavior remain open; macOS build and interactive QA for this addition are pending.
- **Address parsing and search engine — Partial.** The native omnibox supports basic URL-versus-search routing and a saved search engine. It lacks Electron's suggestion matching across tabs/history/bookmarks, keyword search indicators, robust navigation parsing and suggestion keyboard flow.
- **Page zoom — Implemented in code (macOS 26 build verified; runtime QA pending).** Normal HTTP(S) origins save zoom in the active profile; private-tab overrides remain in memory and are cleared when the last private tab closes. View-menu/keyboard actions, an omnibox percentage/reset control, and a Settings reset-all action are wired to WebKit `pageZoom`.
- **Built-in New Tab route — Implemented in code (macOS 26 build verified on `7c1ec82`; runtime QA pending).** New tabs default to `surffish://newtab/`, served locally by `BrowserNewTabSchemeHandler`; the page uses the profile's selected search engine, shows a configurable 12/24-hour clock and optional date, and prefers pinned sites, then recent history, then bookmarks. Private tabs omit recent history. The page has no remote dependency.
- **New Tab customization — Partial, improved in the current code pass (macOS 26 build verified on `7c1ec82`; runtime QA pending).** Settings persist four local color themes, quick-link sources (Automatic, Pinned, Recently visited, Bookmarks), profile-local shortcut add/edit/remove/reorder (HTTP(S)-only, up to 12), and clock format/date visibility/size. Save & Apply refreshes existing built-in New Tabs; private tabs' recent-history links remain hidden. Custom local/remote photo backgrounds and refresh/cache behavior, and weather/location/providers remain missing. Source contracts pass; interactive behavior remains unverified. See [Electron New Tab background handling](https://github.com/PylotLight/Surffish/blob/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87/src/main/new-tab-backgrounds.ts), [weather handling](https://github.com/PylotLight/Surffish/blob/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87/src/main/new-tab-weather.ts), and [renderer New Tab state](https://github.com/PylotLight/Surffish/blob/fbabc6aa03ba3b39eee92ed4388c39fa919f3b87/src/renderer/src/views/Browser.tsx).

### Tabs, navigation history and session

- **Create, select, close and pin tabs — Partial.** Core AppKit/WebKit tab management and saved tab metadata exist; pinned tabs have a strip, title/URL search, and drag reorder within pinned and unpinned partitions. Multi-selection, batch operations, complete tab overview/search, audio/mute indicators and richer tab navigation history are not complete.
- **Duplicate tab — Implemented in this pass (macOS 26 arm64 build passed; runtime QA pending).** The active tab and normal tab context menu can duplicate a tab, preserving private state, pin state and group/Space metadata.
- **Reopen closed tab — Implemented in this pass (macOS 26 arm64 build passed; runtime QA pending).** The menu/shortcut can reopen a bounded in-memory stack of up to 20 non-private tabs. The stack is intentionally not persisted across app relaunches; private tabs are excluded.
- **Find in page — Implemented in code (macOS 26 build verified; runtime QA pending).** A native find bar uses Apple's Swift `WKWebView.find(_:configuration:)` API with case-insensitive wrapping, previous/next and Escape. It shows an independently computed, explicitly approximate text-node count; WebKit exposes only match/no-match here, so there is no Electron-equivalent active ordinal and counts may differ for hidden or split-node text.
- **Groups and Spaces — Partial.** Native tab models persist group/Space metadata, but the Electron interaction model, group management, Space switching and split view are not present.
- **Session restore and window lifecycle — Partial, improved in the current code pass.** A profile-local session restores tab metadata and active selection; only the saved active tab loads immediately, while other restored tabs load once selected. Geometry, multiple windows, robust lifecycle/crash recovery and deferred persistence remain roadmap work. Source contracts pass and macOS 26 build `7c1ec82` succeeded; interactive runtime QA remains pending.
- **Private browsing — Partial.** Private tabs use non-persistent WebKit stores and are excluded from saved sessions/history; this pass also excludes private tabs from reopen-closed history and hides recent history on their New Tab. Private-window isolation and complete data-deletion guarantees still need runtime verification.

### Bookmarks, history and other library surfaces

- **Bookmarks — Partial, improved in code.** Profile-local add/remove and a sidebar list exist, with backward-compatible `isPinned` persistence, pin/unpin context actions, a pinned-site strip, filtered counts, per-panel sorting and manual reorder within pinned/unpinned partitions. Folder hierarchy, manager and imports remain open. Build `7c1ec82` passed on macOS 26; interactive runtime QA remains pending.
- **History — Partial, improved in code.** Profile-local history excludes private visits and supports search, All/Today/7-day/30-day filters, clearing the selected period, removing one entry, clearing a host plus its subdomains, filtered counts, per-panel sorting and opt-in Never/30-day/90-day/1-year retention. Per-tab back/forward menus are available. Broader history navigation remains open. Build `7c1ec82` passed on macOS 26; interactive runtime QA remains pending.
- **Reading list — Partial, improved in code.** A profile-local JSON store supports add/remove, unread/read state and backward-compatible snapshot decoding. Toolbar actions save/remove only normal HTTP(S) pages; private tabs cannot add items. The sidebar can open, mark read/unread and remove entries, and now includes filtered counts and per-panel sorting. Rich offline/article metadata remains open.
- **Bookmark pin migration — Implemented in this pass (macOS 26 arm64 build passed; runtime QA pending).** Older JSON bookmark records that lack `isPinned` decode as unpinned rather than failing the library snapshot.

### Settings, privacy and site controls

- **Settings shell — Partial, modernized in the current code pass.** The AppKit window controller hosts SwiftUI pages for General, Appearance, Privacy, Extensions, Connection and About, with section navigation and search over supported controls. Existing controls remain connected to the WebKit data store, ad blocker, WebKit extension manager and OpenSSH tunnel manager; unsupported Chrome-only behaviors are called out rather than presented as switches. Source contracts pass and macOS 26 build `7c1ec82` succeeded; interactive runtime QA remains pending.
- **Appearance, tab behavior and toolbar configuration — Partial, improved in the current code pass.** New Tab themes, quick-link source, custom shortcuts with reorder controls, 12/24-hour clock, date visibility and clock size are persisted and applied; startup sidebar visibility, keep-open pin and a 220–440-point sidebar width are configurable. Full app theme, tab, toolbar and pinned-action customization are not available.
- **Privacy and data clearing — Partial, improved in the current code pass.** Private tabs, profile-scoped website-data clearing, and history clearing by selected time period or site are available. Granular website-data type/site/time clearing, HTTPS-only behavior and broader site controls remain incomplete.
- **Permissions and certificates — Missing.** There is no production site-permission manager or certificate inspection/trust surface. WebKit permission callbacks and platform prompts need deliberate native UX.
- **Ad/tracker blocking — Partial.** A persisted native WebKit content-rule toggle exists, but the filter set, update/cache/diagnostic behavior and compatibility are intentionally limited. Electron/Chromium request interception is not a parity substitute.
- **Search keywords, spellcheck, watchers, feeds, Read Aloud and local AI settings — Missing.** No native controls or complete native implementations are present.

### Downloads, extensions and page/content tools

- **Downloads — Partial (source checks pass; macOS 26 build verified on `3b593d0`; runtime QA pending).** WebKit navigation-action downloads, server-initiated HTTP `Content-Disposition: attachment` responses and unsupported MIME types are adopted into a profile-local manager with progress, cancel, resume only when WebKit supplies resume data and the originating WebView remains alive, completion history, open/reveal, clear-finished actions, a toolbar popover, searchable full sidebar panel, and destination/ask-before-save settings. Private download metadata is excluded from disk; completed records are removed when the last private tab closes, while active transfers remain memory-only until WebKit resolves them. The corrected macOS 26 arm64 build passed in [workflow run 45719494587](https://github.com/PylotLight/Surffish/actions/runs/45719494587). There is no pause API in WebKit; retry without resume data, file-type/security scanning and broader Electron lifecycle parity remain open.
- **Web extensions and Bramble — Partial.** The POC uses WebKit's extension APIs and has Bramble integration. Chrome Web Store/CRX, background-worker and Chrome API compatibility cannot be assumed; extension-specific parity requires a documented compatibility layer and tests.
- **Reader, translation and Read Aloud — Missing.** No native article extraction, reader controls, translation flow, voice catalog or playback queue.
- **PDF viewer/editor and document tools — Missing.** No native PDF editing, form filling, annotation, signature or page operations.
- **Screenshots and media controls — Partial/missing.** Basic WebKit rendering exists; there is no full-page/scroll capture pipeline, annotation, media session, per-tab volume or cast surface.
- **Feeds and page watchers — Missing.** No native feed discovery/reader, repository presets, region watchers, change detection or notifications.
- **Glance, mini windows, menubar and tab overview — Missing.** No native equivalents yet.

### Networking, diagnostics and performance

- **SSH/SOCKS5 foundation — Partial, substantial.** Native OpenSSH `ssh -D`, profile-separated settings, browser routing and optional external SOCKS sharing exist. Verifying the configured SSH destination/exit host, health state, fail-closed behavior, sleep/wake, local-network bypass, listener observability and runtime tests remain open. This design does not use or require a separate NAS SOCKS daemon.
- **Network inspector, HAR, overrides and request mocks — Native alternative required.** Chromium request interception/DevTools contracts cannot be copied into WebKit. If prioritized, build opt-in instrumentation using only supported WebKit/network surfaces and mark its visibility and coverage limits.
- **Task manager / per-tab process CPU and memory — Native alternative required.** WebKit process ownership and metrics differ from Chromium; do not present Electron process APIs as available in the native app. Native memory diagnostics are not full task-manager parity.
- **Tab sleep/archive, preconnect and wake snapshots — Missing/partial.** No validated native equivalent for Electron's lifecycle/performance features is present.

## Native applicability and explicit non-ports

The following Electron capabilities require native alternatives or an explicit compatibility limitation rather than a blind port: Chromium DNR and `webRequest` interception, DevTools request capture/overrides, Chromium renderer-process metrics, Electron compositor and DOM-driven sidebar morph behavior, and Chrome-only extension APIs. WebKit Web Extensions, `WKContentRuleList`, `WKNavigationDelegate`, AppKit menus and native window APIs are separate mechanisms; one should not be marked equivalent merely because a similarly named settings control exists. The roadmap's WebKit compatibility section remains authoritative.
