# Architecture

Surffish uses a trusted Electron main process, a native `BaseWindow` view tree, three small local React renderer surfaces, and an isolated remote `WebContentsView` for each loaded tab. The active site page is a full-width native view underneath the app chrome. On live sites, transparent toolbar and glass-sidebar surfaces are placed above it; on the local New Tab and full-app panels, the original full React surface is shown instead. New background tabs remain URL-only until selected; restored tabs remain unloaded until explicitly resumed. Loaded tabs continue playing media when inactive, and optional hibernation releases inactive, non-audible views for reuse later.

```text
                     ┌── local full-app renderer (New Tab, settings, full panels)
BaseWindow view tree ├── transparent toolbar renderer (live-site overlay)
                     ├── glass sidebar renderer (zero-width hidden / user-sized overlay)
                     └── per-tab remote WebContentsViews (full-width page, lower layer)
                                      │
                                      └── shared persistent SOCKS5 browser session
```

- `src/main/index.ts` — application startup; restores protected session cookies and configures the browser proxy before creating tabs.
- `src/main/window.ts` — native `BaseWindow` lifecycle, platform chrome, trusted local renderer views, and local renderer loading.
- `src/main/browser-shell.ts` — native view ordering/visibility, measured toolbar geometry, hover/pin state synchronization, and the local-renderer allowlist.
- Persisted browser preferences are read as one snapshot and broadcast to all three local surfaces, keeping pins and the selected search engine coherent when the visible renderer changes.
- `src/main/browser.ts` — lazy per-tab page views, configurable tab hibernation, active-tab switching, full-width page bounds, navigation, and restoration of the last open tabs.
- `src/main/network-inspector.ts` — opt-in per-tab Chromium DevTools Protocol Network capture, a 1,000-request in-memory ring, and on-demand request/response detail lookup.
- `src/main/deferred-writes.ts` — coalesces hot-path writes (session tabs, history, favicon cache, downloads) and flushes them on quit, before `surffish.db` closes. New frequently-updated stores should go through `deferWrite`.
- `src/main/store/` — the profile's SQLite database (`surffish.db`) for history, the window/tab session, bookmarks, preferences and Spaces, with JSON files kept as fallback copies; see [Profile storage](storage.md).
- `src/main/browser-persistence.ts` — open windows/tabs, active tab, and browser preferences (tab-sleep interval, site settings, zoom), saved through `src/main/store/` with the JSON fallback.
- `src/main/session-cookies.ts` — encrypted snapshot/restore of session-only cookies using Electron safeStorage when OS-backed encryption is available.
- `src/main/history.ts` — validated, bounded browsing history, stored in `surffish.db` (falls back to `browsing-history.json`).
- `src/main/proxy.ts` — validates loopback-only SOCKS5 settings, persists them, and configures the persistent site session.
- `src/main/ipc.ts` — browser IPC guarded to the three trusted local renderer views; toolbar geometry reports are accepted only from the toolbar surface.
- `src/preload/index.ts` — narrow, typed browser API exposed through `contextBridge` to the local renderers only.
- `src/shared/navigation.ts` — HTTP(S)-only address parsing and selected-search-engine routing.
- `src/shared/types.ts` — browser, proxy, chrome-state, and toolbar-metrics contracts shared across processes.
- `src/renderer/` — shared React UI rendered as the full app, toolbar-only, or sidebar-only surface according to a trusted URL query parameter.
  - `views/Browser.tsx` — the shell (toolbar, sidebar, New Tab, settings pages). Every surface mounts it, so effects that fetch or subscribe should be gated by `surface` / visibility.
  - `views/NetworkView.tsx`, `DownloadsPanel.tsx`, `ExtensionToolbarButtons.tsx`, `ExtensionsSettings.tsx`, `TabIndicators.tsx` — self-contained features that own their own state; prefer adding new features as files like these instead of growing `Browser.tsx`.
  - `views/settings/SettingsControls.tsx` — `SettingsGroup` / `SettingsRow` / `SettingsSlider` primitives for settings pages.
  - `lib/` — renderer helpers (`stored-state.ts` for small cross-surface localStorage prefs, `format.ts`).
  - Toolbar-surface popups must size in px, not `vh`: the toolbar view is only toolbar-tall until the popup's measured bottom grows it.

## Security and input boundaries

1. Remote content is never loaded into the React renderers. Site `WebContentsView`s use `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, and `webSecurity: true`; they receive no Surffish preload bridge.
2. Remote tabs use Surffish's persistent `persist:surffish-browser` session, which stores site cookies/storage and uses the configured SOCKS5 proxy.
3. Local UI IPC is accepted only from the content, toolbar, or sidebar WebContentsViews created by `window.ts`. Remote site pages cannot call those handlers.
4. Native stacking places the live page below the transparent local surfaces. The full React content surface is made invisible while a web page is active, so its full-window hit-test rectangle cannot intercept site clicks or scrolling. The toolbar and sidebar remain bounded overlays; while hidden, the sidebar has zero native width and the page's own mouse-move events reveal it after a short hover delay without reserving or blocking a pixel.
5. Non-HTTP(S) navigations, unapproved popups, and web permission requests retain their existing blocking policy. SOCKS settings accept loopback hosts only.

## Private tabs

`New Private Tab` (⌘/Ctrl+Shift+N, or the mask button next to New Tab in the sidebar) opens a tab in `surffish-private`, an in-memory partition created lazily by `getPrivateSession()` in `src/main/browser-session.ts`. Modules that configure page sessions register with `onPrivateSessionCreated` (proxy + permission policy, ad blocking, downloads); private pages wait on `whenPrivateSessionReady()` so nothing loads before the SOCKS proxy is applied, and a failed setup blocks the load instead of going direct. Private tabs are excluded from the saved session, history, favicon cache, recently-closed list, extension `chrome.tabs` APIs and the Google WebKit sign-in hand-off; their downloads are listed for the session but never written to download history. Closing the last private tab clears the partition's storage, cache, auth and host caches. Web Store extensions and Bramble are not loaded into the private session.

## Glance (link peek)

Shift+click a link (or right-click → **Open Link in Glance**, or ⌘K → **Open Copied Link in Glance**) and it opens in a floating sheet over the current tab instead of a new tab. Settings → General → Glance turns the Shift+click part off; then Shift+click behaves as before (Chromium's `new-window` disposition, still blocked unless the site allows popups as tabs). A Shift+clicked link is told apart from a script popup by its disposition (`new-window`) with no size features (`isShiftClickLinkOpen` in `src/shared/glance.ts`).

- `src/main/glance-entry.ts` is all main loads at startup: the setting, IPC, and the hooks browser.ts calls. `src/main/glance.ts` (the sheet) is a lazy chunk imported on the first open, so Glance costs nothing at launch.
- One glance per window, two views added on top of everything in the window: a transparent local view (`glance-page.ts`, preload `glance.cjs`) that draws the dimmed backdrop, the rounded card and its header (title/URL, Back, Split View, Open as Tab, Close), and the page itself, a `WebContentsView` with a tab's webPreferences in the **source tab's session**, so private tabs, Spaces and per-site proxy rules apply unchanged. The header view is loaded before it is attached, so it never takes keyboard focus from the page.
- Esc, ⌘/Ctrl+W or a press on the backdrop close it and destroy both webContents. Any other browser shortcut (⌘T, ⌘K, ⌘L…) closes the glance first and then runs. The glance also closes when its tab leaves the screen (tab switch, tab closed) or the window closes.
- ⌘/Ctrl+Enter (or **Open as Tab**) promotes it: the page's own view becomes a new tab right after the source tab, so nothing reloads and back/forward history is kept. **Split View** does the same and shows the new tab in a split next to the source. (A webContents can't be handed to a second `WebContentsView`; trying hangs main, so the tab takes over the view itself.)
- Links inside navigate within the glance (plain clicks, `target=_blank` and Shift+click); ⌘/Ctrl+click still opens a background tab. Visits go to history like a tab's, except from private tabs.
- Diagnostics lists an open glance (`Glance: host`). `onGlanceLinkHover` in `glance-entry.ts` feeds preconnect: links hovered inside a glance preconnect like tab links do (same 200 ms dwell, in the glance's session).
- Coverage: `test:electron-glance` (real Shift+click input, navigate inside, promote without reload, split, Esc/backdrop/tab-switch close, no leaked webContents or renderer processes, setting off, private session).

## Mini window

**Pop Out to Mini Window** (tab right-click menu, ⌘K, Window menu, ⌘/Ctrl+Shift+M) moves a tab's page into its own small frameless window that stays above other apps, for an AI chat, a video or docs while working elsewhere. **Return to Browser** (the header's ⇱ button, ⌘K, Window menu, or ⌘/Ctrl+Shift+M again in the mini window) moves it back. The page's own view moves both ways, so nothing reloads and its state (typed text, scroll, media) is kept.

- `src/main/mini-window-entry.ts` is all main loads at startup: settings (`browser-mini-window.json`), IPC, the global toggle shortcut and the calls menus/palette make. `src/main/mini-window.ts` (the window) is a lazy chunk imported on first use.
- In browser.ts the mini window is a `BrowserWindowState` with `mini: true`, no shell surfaces and exactly one tab. It is not registered with window-scope, so "the current window" never resolves to it (menus, ⌘T, the palette act on the browser window). The tab keeps every tab behaviour (history, favicons, crash handling, session save), and as its window's active tab it counts as on screen: timed sleep, the memory saver, auto-archive and wake-snapshot capture leave it alone. Tabs it would open (links, context menu, popups-as-tabs) go to a browser window (`browserTargetForMini`), never into the mini window. Shift+click opens a background tab instead of a Glance. Page commands pressed in it (reload, back/forward, zoom, close) act on its tab; window-level ones go to the browser window.
- Several mini windows (up to 6, `MINI_WINDOW_MAX`): each popped-out tab gets its own window and popping out another never sends one back; past the cap the pop out is refused with a notice in the browser window. A new one opens off the newest one on that display, stepped 28 px toward the middle until no open mini window sits at the same spot (`cascadeMiniBounds`). The global toggle (and ⌘K / Window menu **Show/Hide Mini Windows**) shows or hides all of them together: any on screen → all hide (docked ones tuck), none → all come back (docked ones slide out), the last used one focused. **Return All Mini Windows** (⌘K, Window menu) puts every tab back; ⌘/Ctrl+Shift+M or the header's ⇱ in one returns just that one. The Window menu lists each open mini window by title, and with two or more open ⌘K adds per-window Show / Tuck Away (Slide Out) / Return commands; the plain Tuck command acts on the last used one. Each window takes the lowest free slot (0–5), which keys its remembered size/position and dock. Popping out a window's last tab leaves a New Tab behind. Return goes to the window the tab came from, else the last focused browser window, else a new window (macOS keeps running with only the mini window open). Closing a browser window never closes a mini window; quitting saves each mini tab as a last tab of its home window, so a restart restores it as an ordinary tab.
- macOS: an NSPanel (`type: 'panel'`) at the `floating` level, `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true, skipTransformProcessType: true })`, shown with `showInactive` when a tab pops out (the browser window keeps focus) and focused when summoned by the shortcut. Elsewhere: a frameless `alwaysOnTop` window. Opacity (Settings, 40–100 %) applies on macOS/Windows.
- Header: a local data: page (`mini-window-page.ts`, preload `mini-window.cjs`) over the page's top edge with favicon/title/host, Back, Reload, Return and Close. It is zero-height until the pointer comes within 44 px of the top (the page's `before-mouse-event`), and hides ~0.7 s after the pointer leaves (a cursor poll runs only while it is shown). It is draggable; the window is resizable. The header is loaded before it is attached (no focus steal) and is watched by crash-guard like the browser surfaces; a crashed page reloads under tab-health's auto-reload budget, since the crash screen lives in the browser window's content surface.
- Size and position are remembered per slot per display (keyed by work area, `mini-window-geometry.json` as `{ slots: [...] }`; the older single-window file, a bare per-display record, reads as slot 0); it opens on the display under the pointer, bottom-right the first time, and snaps into a corner when dropped within 32 px of one.
- Tuck to screen edge (`src/shared/mini-window-dock.ts` pure geometry, `src/main/mini-window-dock.ts` in the same lazy chunk). Dropped with 24 px or more of the window pushed past an outer edge of its display's work area, or with the pointer pressed against the display's edge over the window (the only way to reach the top on macOS, which stops windows at the menu bar), the window docks to that edge and slides off it (180 ms ease-out with stepped `setBounds`, instant with `prefersReducedMotion`), then hides. Edges shared with another display never dock (the window would just appear on the neighbour). A handle tab stays behind: its own small frameless, transparent, `focusable: false` window (NSPanel at the `floating` level on every Space and over full-screen apps on macOS, `alwaysOnTop` elsewhere) with a local data: page (`mini-window-handle-page.ts`, same preload). The handle rides the window's inner edge: tucked it sits on the screen edge, out it sits on the window's free side pointing back. Click slides the window out (focused) or tucks it; dragging the handle moves both along the edge (main follows the cursor while the page holds pointer capture). The header's chevron button tucks to the nearest outer edge, and while docked the global toggle shortcut (and Show/Hide Mini Window, ⌘K "Tuck Mini Window to Screen Edge") slides it out and in instead of hiding it. Dragging the window more than 48 px away from its edge undocks it. Several windows dock independently, each with its own handle; handles tucked on the same edge of a display are spread along it so they never overlap (`spreadDockHandles`: order follows where each window sits along the edge, so dragging one past another swaps them, and the rest re-spread when one slides out, undocks or closes). The edge and the place along it are remembered per slot per display (`mini-window-dock.json`, `{ slots: [...] }`, old single-window file read as slot 0), so the next pop out on that display opens against the same edge; display changes re-check the edge (moving to the nearest outer edge, or undocking when none fits). Tucking only hides the window: the tab stays its window's active tab (never slept, discarded or archived) and media keeps playing; a hidden page stops painting, so a static page idles at ~0 % CPU. Settings → General → Mini window → Tuck to screen edge (on by default) and Peek on hover (off by default: resting on the handle slides the window out until the pointer leaves it; a click inside keeps it out).
- Settings → General → Mini window: a default page (empty by default) and the global toggle shortcut (default ⌘⇧Space / Ctrl+Shift+Space; record by pressing keys, Clear turns it off). The shortcut opens the default page in the normal profile session (Default Space, so signed-in sites stay signed in) when the mini window is empty, else shows/hides it; without a default page it pops out the current tab. A shortcut that Surffish already uses, or one another app holds (`globalShortcut.register` fails), is not registered and Settings says why. A private tab popped out stays in the private session.
- Coverage: `test:electron-mini-window` (pop out/return without reload, always-on-top flag, header reveal, tab sleep and auto-archive skip it, ⌘/Ctrl+Shift+M both ways, toggle path with a pinned page in the normal session, hide/show, links open in the browser window, closing the browser window keeps it, private tab) and `test:electron-mini-window-dock` (tuck to each edge, on-top handle on that edge, handle click restores size flush with the edge, undock by dragging away, header button, toggle and palette, sleep/archive skip and no reload while tucked, audio keeps playing, idle CPU while tucked, remembered edge on the next pop out, setting off).

## Perceived speed: preconnect and wake snapshots

**Preconnect** (`src/shared/preconnect.ts`, `src/main/preconnect.ts`; Settings → General → Tabs → "Preload pages for faster browsing", on by default). About 150 ms after the last keystroke in the address bar (2+ characters), the renderer sends the typed text and the top suggestion's URL to main, which calls `session.preconnect({ url: origin, numSockets: 1 })` on the active tab's own page session, so its SOCKS proxy, per-site route and Space partition apply. Without a suggestion the text is resolved like Enter would (custom keywords included) and only the origin is used, so a search reaches the engine's origin and never sends the query. Resting the pointer on a link for ~200 ms (`update-target-url`, the same signal as the link status bubble) does the same for the link's origin. Each origin is preconnected at most once per 10 s per session. Never from private tabs (typing there must not reach the network before Enter) and never while the proxy kill switch is blocking traffic, since a preconnect is not a request and the request gate cannot see it. `speculativePreconnect(url, context)` is exported for other entry points (e.g. a Glance preview).

**Tab sleep and memory saver** (`src/main/browser.ts`, `src/shared/memory-saver.ts`, `src/main/memory-saver.ts`, `src/shared/tab-sleep.ts`). The timed sleep (Settings → Tabs, minutes) counts from when a tab left the screen and re-arms every background tab when the setting changes. The memory saver samples every 30 s (only when some tab could be discarded) and discards at most two least recently used background tabs per check. On macOS it reads `kern.memorystatus_vm_pressure_level` and `kern.memorystatus_level` (the kernel's available percentage, reclaimable memory included) in one `sysctl`; warning level counts only when that percentage is also low, critical always counts, and the summed working set (which double counts shared pages there) only counts under kernel pressure. Short of critical pressure it never discards a tab seen in the last 15 minutes or sooner than the user's own sleep timer (an hour when the timer is off); critical pressure goes down to 5 minutes. Each sleeping tab carries why it sleeps (restored and never loaded, idle timer, memory saver, by hand, crashed), shown in the sidebar moon's tooltip; restored tabs' moons are fainter.

**Wake snapshots** (`src/shared/wake-snapshot.ts`, `src/main/wake-snapshot.ts`, `src/renderer/src/lib/wake-snapshot-layer.ts`). A hidden, detached page cannot be captured (`capturePage` never resolves), so the picture is taken when a tab leaves the screen (switching away, or opening a new foreground tab), only for a tab that was on screen for 1.5 s or more, so bursts of tab opening pay nothing: the capture the tab overview thumbnail is made from (`stayHidden`, so a pending capture never keeps a detached tab visible) is also kept, encoded ~300 ms later off the switch's paint path (the small overview thumbnail first, the snapshot on its own task), as a JPEG at the capture's own device pixels (2x on Retina, scaled down only past 3840 px) at quality 80 so text stays readable, in main-process memory only (never on disk, private tabs included), at most 32 MB in total (oldest go first) and 3 MB each (a text page at 2880 px is ~0.6 MB). When a sleeping or discarded tab (timed sleep, memory saver, Hibernate Tab) is opened on its own (not in a split), with the same URL and about the same page-area size, the toolbar surface is stretched over the window and draws the picture under its own UI while the new page view loads underneath at full priority. The picture cross-fades out (180 ms, none with reduced motion) on the page's first contentful paint (read from an isolated world), else 150 ms after `did-finish-load`, and it never stays longer than 8 s. A failed load, a crash, a tab switch, closing the tab or leaving the overlay layout takes it down at once. Input never stops at the picture: a press or scroll that lands on it (rather than on toolbar UI) takes it down and is sent to the page with `sendInputEvent` (a press keeps the cover until its release so the click stays whole), and keyboard focus stays on the page. Snapshots are dropped once shown, when their tab closes, and when private browsing ends. A sleeping tab also keeps its back/forward list (`navigationHistory.getAllEntries()`, whose page state carries scroll position and form values) and wakes through `navigationHistory.restore`, a history load that prefers the HTTP cache like Back does, so the page comes back where it was under the snapshot instead of reloading at the top; a tab whose URL changes while asleep loads the new URL instead. Resting the pointer on a sleeping tab in the sidebar for ~200 ms preconnects the origin it will wake to (preconnect.ts rules: its own session, never private, once per cooldown). `test:electron-perceived-perf` covers both features.

## Network inspector

The inspector is a debug tool and is off by default (Settings → General → Developer). Nothing is attached until it is enabled and the Network view is first opened; rows are only streamed to the renderer while the view is open, and turning it off detaches from every tab and drops recorded rows. Once on, the Network panel attaches Electron's DevTools Protocol debugger to each loaded tab before its page navigation. It records request/response metadata and failures without installing another session-level `webRequest` callback, so the ad blocker keeps the session's single `webRequest` hook (Electron allows one listener per event; `src/main/adblock-engine.ts` owns it). The newest 1,000 requests are retained in process memory; request/response headers and bodies are fetched for the selected row, and response bodies are not retained unless requested. Clearing the panel drops the retained rows, and closing the app discards them. Since full DevTools headers can include cookies or authorization values, they are visible only in the local inspector and are not written to browser history or the profile.
